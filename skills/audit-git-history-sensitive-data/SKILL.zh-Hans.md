# 审计 Git 历史敏感信息

执行只读审计。报告证据时不暴露敏感值，不改写、不删除、不推送，也不清理
Git 对象。

## 确定范围

先读取仓库说明，再确定仓库与可达历史范围：

- 默认检查 `HEAD` 可达的提交；
- 只有用户要求全部本地引用时才使用 `--all`；
- 遵守用户给出的引用、SHA 端点、日期和作者过滤条件；
- 单独记录 submodule 和 Git LFS；普通 Git 对象遍历不会检查其外部对象库。

只读检查：

```bash
git status --short --branch
git rev-parse --show-toplevel
git log --date=iso-strict --format='%H%x09%aI%x09%an%x09%ae%x09%s' <scope>
git rev-list --objects <scope>
```

## 扫描可达历史

优先复用已安装且支持历史扫描的密钥检测工具，不要只为本次审计新增依赖。
无论使用什么工具，都要检查以下表面：

1. 提交消息、作者与提交者元数据、文件名和符号链接目标；
2. 每个唯一可达 blob，并映射到暴露它的全部提交和路径；相同 blob 不重复扫描；
3. 已删除或重命名的文件，不能只检查当前工作树；
4. 文本和可解码的结构化文件；无法读取的二进制文件应标记为待复核，不能视为
   已确认安全。

至少覆盖：

- API Key、访问令牌、密码、Cookie、私钥、证书、连接串和凭据赋值；
- `.env`、本地配置、Shell 历史、云凭据、数据库、备份、归档和调试转储；
- 姓名、个人邮箱、手机号、住址、证件号、账号及其他个人信息；
- `/Users/<name>/`、`/home/<name>/`、`C:\Users\<name>\`、`file://`
  URL，以及日志或工具元数据中的本机绝对路径。

模式或熵命中只是候选，不是定论。结合上下文验证，但不要向凭据所属服务发起
验证请求。区分预期的 Git 作者元数据与误提交到仓库内容中的个人信息；若符合
用户策略，两者都要报告。

## 保护敏感输出

禁止输出完整命中值。使用脱敏内容，并以检测器名称或单向摘要标识结果。不要
把原始命中写入仓库、Shell 历史、命令参数或聊天输出。确需保存详细材料时，
写入系统临时目录并限制文件权限。

## 报告

报告以下内容：

- 精确范围、引用、提交数和已扫描表面；
- 严重性与置信度；
- 首次可达提交、缩写对象 ID、路径和可用时的行号；
- 分类与脱敏证据；
- 对指定引用是否仍然可达；
- 扫描器限制和未检查的外部对象库。

只有提交元数据、路径和可达 blob 内容都检查完成后，才能报告零发现。修复建议
单独给出；只有用户明确要求改写历史时才执行修复。
