# 全项目审查

## 边界与参考

- 输出发现，不自动修复代码。保留被审查项目、持久用户状态和外部业务状态；临时证据可写入系统临时目录。明确要求的写入沿用已有授权。
- 不安装或升级依赖，不切换或清理工作区，不读取 `.env*`、密钥、证书、登录态文件或浏览器缓存。授权后的浏览器访问遵循下方 UI 参考。
- 用[审查矩阵](references/audit-matrix.md)确定维度及所需证据。[报告契约](references/report-contract.md)是台账字段、覆盖率公式、发现字段和完成状态的唯一判定来源，建立台账前读取两者。
- 只按已识别的项目形态加载专项参考：[React/Next.js](references/framework-react-next.md)、[Vue/Nuxt](references/framework-vue-nuxt.md)、[独立 Node.js](references/framework-node.md)、[Monorepo](references/monorepo.md)。
- 包含前端应用时，还需读取[UI 运行时审查](references/ui-runtime-review.md)；仅在用户明确排除 UI 时跳过并披露范围变更。

## 1. 冻结快照

1. 读取用户范围、适用项目说明及必要架构文档。
2. 默认审查当前文件系统，包括相关已跟踪修改和未跟踪文件。明确指定引用或目录时遵守该范围，不切换或覆盖工作区。
3. 记录时间、根目录、范围、分支、提交和初始工作区状态；非 Git 项目记录根目录及范围边界。快照标识还应涵盖范围内未提交内容。
4. 排除生成或缓存产物、包管理器缓存、报告、大体积无关目录、敏感文件和登录态目录。未明确纳入时忽略 SVG，记录各项排除。

**门槛：** 快照及纳入、排除范围可复现。

## 2. 建立项目地图与台账

1. 识别包、工作区、框架、入口、路由、服务端及数据库边界、测试、构建和部署配置。
2. 把生产源码、共享代码、测试、配置、脚本、Schema、迁移、清单、锁文件、代码生成入口和架构文档列为审查单元。
3. 按报告契约记录每个单元，将语义审查进度与必要命令、运行时验证分开，候选发现另按证据置信度分类。
4. 对源码、测试、配置和文档执行语义阅读。锁文件等机器生成结构化单元可由完整内容的确定性工具验证覆盖。文本搜索只能定位证据，不能完成语义审查。
5. 台账放在系统临时目录，其他位置仅在授权后持久化。大范围按不重不漏的批次拆分，每批结束更新台账，不静默抽样。

**门槛：** 每个工作区和必需单元都有范围处置、适用维度及所属批次。

## 3. 执行安全诊断

1. 确定现有包管理器，以及项目已有的 lint、typecheck、test、build 命令。
2. 检查命令及其配置是否联网、写源码或业务数据、更新快照、调用外部服务、迁移或触发生命周期钩子。
3. 仅运行安全、非交互且相关的命令。产生项目产物、缓存、快照、浏览器资料或其他持久文件的命令，需要覆盖这些写入的授权。沿用已有授权，否则记录受阻验证。
4. 不连接生产环境，不执行迁移、seed、发布或可能写业务数据的命令。开发服务器仅在本机监听，且确认不会加载生产配置或访问生产服务后才启动。
5. 授权写入前后比较工作区，披露变化路径，不删除已有内容或擅自清理产物。
6. 记录命令、退出状态和可复查错误摘要，区分代码失败、环境失败和依赖缺失。确认超时或停滞后停止命令，并记录继续方式。

**门槛：** 每个适用诊断项都有结果或受阻原因。

## 4. 审查工作包

1. 分配全部十个审查维度，说明不适用原因。
2. 子代理可用且已获授权时，将独立只读工作组合成三至四个包；否则顺序执行相同边界。建议组合：架构/正确性/数据，可维护性/废弃代码/依赖，性能/UI/无障碍，测试/构建/可观测性/安全基线。
3. 每个包返回审查子状态、必要验证结果、候选发现、证据定位器和未知事项。
4. 主代理维护台账，核对重叠与遗漏，验证跨包结论并去重。

**门槛：** 每个已分派批次均返回证据及明确的剩余工作。

## 5. 验证 UI

前端范围内清点每条路由，静态审查页面、布局、状态及关键流程。启动安全、浏览器选择、授权登录态、视口、交互检查和资源关闭遵循 UI 参考。路由模板冒烟覆盖和核心流程验证与源码审查分别记录，受阻路由保留在台账中。

**门槛：** 路由清单、运行时结果和缺失证据均已记录。

## 6. 验证发现并排序

1. 每条确定性发现满足报告契约字段。单文件内因果完整且排除合理替代解释的静态链可以充分；跨文件、运行时、框架行为或定量主张需独立支持来源，例如调用链、配置、测试、浏览器行为、测量或匹配版本的官方文档。
2. 废弃代码结论先排除约定入口、自动导入、动态加载、插件、反射、生成流程及公共消费者，再分为已确认、高概率或待调查。
3. 有价值但证据不足的线索保留为待调查，写明缺失证据和下一步检查。待调查项本身不代表审查未完成；未完成的必要审查或验证仍须在台账中记为待处理或受阻。
4. 未测量的性能和包体积收益标为静态推断。版本敏感行为或迁移建议须核对匹配项目版本的官方文档，可用时通过 Context7 查询；无法核验时降低置信度。
5. 安全工作限于基线，深度审计转交专门技能，不读取秘密或进行攻击性验证。
6. 按根因去重。缺陷和风险用 P0 至 P3；优化与重构按收益、置信度、成本和回归风险排序。审美偏好与可用性、无障碍缺陷分开。

**门槛：** 确定性发现满足证据要求，待调查项披露不确定性，每项结果有唯一编号及行动档位。

## 7. 报告

按报告契约派生完成状态，分别展示审查覆盖、必要验证和待调查事项。默认在对话中输出 Markdown，仅在要求时持久化报告。受阻项给出剩余批次及继续方式。临时台账丢失时从项目地图重建，不凭记忆编造完成情况。
