# Node.js 审查参考

只在项目地图确认存在独立 Node.js 服务、后端、任务进程、CLI 或运行时包时读取本参考。前端工具链中的 Node.js 配置仍由相应构建维度审查，不自动视为独立后端。

## 建立运行时地图

1. 从清单、锁文件、`engines`、容器或部署配置确认 Node.js 版本约束、包管理器、ESM/CJS 模式和启动入口。
2. 识别 HTTP 服务、队列消费者、定时任务、CLI、worker、数据库与缓存客户端、外部 API、文件系统和进程级单例。
3. 追踪从入口到路由、控制器、领域逻辑、数据访问和外部副作用的关键成功与失败路径。
4. 清点所有长期资源：服务器、连接池、流、事件监听器、定时器、子进程、worker 和后台 Promise。
5. 对 Node.js API 行为、版本支持、ESM/CJS 互操作、废弃 API 或迁移建议，使用实际运行时版本的当前官方文档核验。

## 正确性与生命周期

- **启动边界：** 检查模块导入是否意外启动监听、任务或写操作；确认应用构造与进程启动是否可分离并可测试。
- **错误传播：** 检查同步异常、Promise rejection、回调错误、事件发射错误和后台任务失败是否到达明确处理边界，不被吞掉也不导致无上下文退出。
- **停止流程：** 检查 SIGTERM、SIGINT、部署终止和测试清理是否停止接收新工作、等待在途任务、关闭服务器与连接，并设置有界超时。
- **取消与超时：** 对网络、数据库、队列和子进程检查超时、取消、重试与退避；重试写操作时检查幂等和重复副作用。
- **并发：** 检查无界 `Promise.all`、重叠定时任务、共享可变状态、重复消费、竞态更新和缺失背压。
- **流与事件：** 检查流错误、提前关闭、pipeline、背压与销毁；检查 EventEmitter 监听器是否重复注册或未移除。没有调用链或运行证据时不要宣称内存泄漏。
- **定时器与后台任务：** 检查句柄是否可停止，异步回调是否捕获失败，任务是否会重入，以及进程退出是否被无意阻塞。

## HTTP、API 与数据边界

- 在路由边界检查参数、查询、正文、Header、文件和外部消息的运行时验证；TypeScript 类型不能替代不可信输入验证。
- 检查身份、授权与租户边界是否在业务数据访问前执行，且失败状态码和错误结构一致。
- 检查响应只发送一次，异步错误能进入框架错误处理，流式响应在客户端断开时释放上游资源。
- 检查超时、请求体限制、上传大小、分页上限、速率约束和资源放大风险；只报告与可达路径相关的项。
- 检查数据库事务边界、连接释放、N+1 查询、批量写入、唯一约束、幂等键和失败后的状态一致性。
- 检查文件路径、URL、命令参数和模板输出是否由不可信输入构造；安全基线只做非攻击性的源码与配置验证。
- 检查错误是否泄露堆栈、内部路径、SQL、令牌或用户数据；不要为验证而读取真实密钥或 `.env*`。

## 性能与可观测性

- 找出请求路径上的同步文件 I/O、CPU 密集循环、大对象序列化、无界缓存和阻塞式加密或压缩。
- 对事件循环阻塞、内存泄漏、吞吐或延迟结论要求 profile、heap、指标或稳定复现；仅凭代码形态只能标为静态推断。
- 检查数据库和外部 API 是否存在串行瀑布、重复查询、缺少连接复用或无界并发；优化建议要说明测量方法。
- 检查日志是否有稳定级别、请求或任务关联标识、错误上下文和敏感字段处理；不要要求无差别记录所有输入。
- 检查健康、就绪与优雅退出信号是否反映实际依赖状态，监控是否能区分业务失败与进程存活。

## 模块、依赖与废弃代码

- 检查 ESM/CJS 混用、条件导出、别名、运行时加载、插件注册和 CLI `bin` 入口，避免把动态或外部调用入口判为废弃代码。
- 公共包导出、框架钩子、任务处理器、迁移、seed、运维脚本和代码生成入口不能只凭无静态引用判死。
- 未使用依赖结论必须覆盖生产源码、类型、测试、配置、脚本、加载器、预加载模块和部署构建。
- 检查依赖版本或过时 API 时关注真实兼容性、安全或维护影响；“不是最新版”本身不构成发现。
- 对可删除代码按“已确认”“高概率”“待调查”输出，并列出已排除的动态、约定和公开接口路径。

## 安全命令与完成门槛

- 运行命令前读取脚本和相关配置；不要自动执行迁移、seed、生产写入、真实外部服务调用、发布或破坏性测试。
- 优先运行已确认安全的 typecheck、lint 和隔离测试。若测试入口本身危险或会写业务数据，记录脚本证据并跳过。
- 只有在全部入口、关键成功与失败路径、资源生命周期、API 和数据边界、依赖用途及适用质量门禁均已覆盖时，才标记 Node.js 专项完成。
- 单文件内因果完整的确定性静态证据可以闭合语义审查；涉及跨文件生命周期、实际时序、泄漏、吞吐或延迟的结论仍需第二证据。代码失败可作为已完整执行的验证证据；依赖缺失、无法安全运行、外部系统不可用、必要测试或明确适用的运行时验证未执行时，不满足本完成条件，记录受阻项并使总体状态为“部分完成”。
- 每条发现必须给出文件与行号或命令证据、证据类型、影响、置信度、成本、回归风险和可执行验证方法。
