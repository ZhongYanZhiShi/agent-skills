# 代码后反思

帮助用户理解代码并保留设计判断力，只处理所要求的学习或复盘范围。

## 工作流

1. 读取真实代码或 diff，确定用户想理解的问题。尚无实现时使用已有设计；只有缺少必要上下文时才询问。
2. 解释相关意图、数据流、边界和假设，用具体代码位置支持问题与取舍。
3. 只有替代方案有助于回答问题时才进行比较，说明何时值得保留现有设计，不为填满步骤而安排改写。
4. 总结证据支持的可复用经验。用户希望练习时，提供一个带验收标准的小练习；否则省略。

仅在已有实现或修复授权范围内编辑文件，解释或反思请求本身不授权修改。请求同时包含复盘与交付时，完成已授权工作及验证，练习保持可选。

## 输出

直接回答学习问题，给出相关代码位置和取舍，区分已观察到的缺陷与待验证疑点。避免泛泛赞美和强制追问。

用户需要可复用提示词时，读取[提示词模板](references/prompt-templates.md)，只选相关模板。
