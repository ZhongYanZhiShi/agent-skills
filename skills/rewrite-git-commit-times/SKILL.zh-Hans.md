# 整理 Git 提交时间

只改写时间元数据。提交树、消息、身份、源引用、当前工作区和远端保持不变。

## 确定规则

修改前确定：

- 一个或多个半开工作时段，例如 `[09:00,12:00)`、`[14:00,18:00)`；
  用户未提供时必须先取得工作时段，不能自行猜测；
- 默认使用用户电脑当前 IANA 时区，除非用户明确指定其他时区；
- 作者邮箱默认使用仓库当前生效的 `git config user.email`；缺失时要求明确
  提供，处理全部作者必须得到明确同意；
- 源引用，以及一个独立、已存在的本地目标分支。

用户未说明日期范围时，只选择“原提交者时间”在已解析时区中属于当天的提交。
把当天的具体日期写入规则文件，避免后续执行跨过午夜。明确范围使用包含首尾的
`start`/`end`，全部日期使用字面量 `all`。

电脑可以提供 IANA 时区时，不能只根据 UTC 数字偏移猜测时区。不要猜工作时间。

## 为明确日期范围确定节假日

只有默认“当天”可跳过联网查询。只要用户明确给出单日、日期范围或 `all`，
就执行：

1. 节假日地区与时区分开确定。优先使用用户指定地区；未指定时，只有电脑地区
   信息明确才能采用，存在歧义则在写入前询问；
2. 确定所选提交覆盖的全部年份；`all` 先只读检查匹配提交；
3. 每个所需年份都在系统临时目录查找
   `<country>_holiday_schedule_<YYYY>.md`，国家名称使用小写 slug，例如
   `china_holiday_schedule_2026.md`；
4. 对应年份的文件存在且包含日历数据时直接读取，不按抓取月份或文件时间过期；
5. 文件不存在或为空、日历数据无法使用，或用户明确要求“重新查找”时查询官方
   来源。重新查找必须绕过缓存，并在新数据验证成功后再替换缓存。

只有节假日地区确定为中国大陆（`china`）时，才使用国务院搜索页并递增
`pageNo`：

```text
https://sousuo.www.gov.cn/sousuo/search.shtml?code=17da70961a7&searchWord=%E8%8A%82%E5%81%87%E6%97%A5%E5%AE%89%E6%8E%92%E7%9A%84%E9%80%9A%E7%9F%A5&dataTypeId=107&pageNo=<N>
```

该地址不是全球节假日来源，不得用于香港、澳门、台湾或其他国家和地区。其他
地区必须查找当地政府官方来源，并按各自国家或地区 slug 独立缓存。

打开所需年份的正式通知，从通知正文提取包含首尾的放假日期范围和明确调休
上班日，不能把搜索摘要直接当成日历。每年单独缓存抓取时间、地区、标准化日期
和来源 URL。官方安排不存在时停止，不能猜测。

## 生成规则文件

把 JSON 规则写入系统临时目录：

```json
{
  "timezone": "Asia/Shanghai",
  "date_scope": {
    "start": "2026-07-01",
    "end": "2026-07-31"
  },
  "author_emails": ["developer@example.com"],
  "work_windows": [
    {"start": "09:00", "end": "12:00"},
    {"start": "14:00", "end": "18:00"}
  ],
  "holidays": [
    {"start": "2026-10-01", "end": "2026-10-07"}
  ],
  "workdays": ["2026-10-10"]
}
```

省略 `date_scope` 时脚本会立即解析当天；优先写入已经确定的具体日期。只有
用户明确要求全部日期时才使用 `"date_scope": "all"`。只有明确要求全部作者
时才使用 `"author_emails": ["*"]`。日期范围包含首尾；工作时段采用半开、
有序、不重叠且不跨午夜的区间。`workdays` 覆盖普通周末，`holidays` 覆盖
普通工作日，两组日期不能重叠。

## Dry-run 与执行

先检查项目说明、状态、引用、worktree、签名和选中提交数。脚本只接受线性源
历史；没有单独明确要求时，不要自动展开 merge。

```bash
python3 scripts/rewrite_commit_times.py --self-test

python3 scripts/rewrite_commit_times.py \
  --repo <repo> \
  --source <linear-source-ref> \
  --target <existing-target-branch> \
  --rules <rules.json>

python3 scripts/rewrite_commit_times.py \
  --repo <repo> \
  --source <linear-source-ref> \
  --target <existing-target-branch> \
  --rules <rules.json> \
  --apply
```

默认只 dry-run。执行 `--apply` 前展示时区、范围、作者策略、工作时段、日历
来源、选中数、改动数、目标和签名影响。公开或共享仓库、签名失效、替换源引用
或发布远端时，必须再次取得明确确认。禁止自动强推或跳过钩子。

`--apply` 重建线性提交链，把源/结果 TSV 映射写入系统临时目录，验证后原子
更新目标引用。目标分支被任一 worktree 检出时拒绝执行。

## 验证

确认：

- 只有按原提交者日期和作者策略选中的提交获得新时间；
- 选中提交的作者与提交者时间都落在工作日的工作时段内；
- 提交数、树、消息、姓名和邮箱保持一致；
- 源引用、工作区、无关文件和远端保持不变；
- 目标历史没有缺失对象。

最终报告目标新 HEAD、选中数与改动数、日历来源或缓存路径、映射路径、签名
影响和发布状态。内容敏感信息审计属于 `audit-git-history-sensitive-data`；
历史清洗必须使用单独批准的修复流程。
