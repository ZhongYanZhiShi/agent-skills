# 安全重写 Git 历史

在不修改源分支和无关工作区状态的前提下重建 Git 历史。把内容清洗、
拓扑调整和时间改写拆成独立阶段，并在阶段之间完成明确验证。

## 锁定执行约定

修改前确认以下决策：

- 源引用、目标分支，以及目标基线或孤儿根策略；
- 有界提交范围：使用精确 SHA 端点和/或明确日期时间端点，并限定准确作者身份；
- 提交顺序与合并策略：保留拓扑或线性展开；
- 空提交策略和必须保持不变的元数据字段；
- 需要删除或匿名化的敏感路径、密钥模式、数据库、本地配置和个人值；
- 时区、节假日、补班日、禁用时段、移动方向和区间边界；
- 仅保留本地还是发布远端。

作者身份默认取当前仓库生效的 `git config user.name` 和 `user.email`；
任一配置缺失时，要求用户明确提供作者。范围或作者未提供时，禁止解释为全部
可达历史或全部作者。日期时间边界必须注明时区，以及每个端点是否包含。

修改前判断仓库属于个人项目还是他人/共享项目，并判断仓库为私有还是公开。
存在远端时使用已认证的托管平台元数据，不能仅凭远端 URL 推断可见性。无法
验证归属或可见性时，按需要二次确认处理。若是非个人项目，或个人项目的公开
仓库，先完成只读检查或 dry-run，再展示已解析的仓库、分类、范围、作者、受
影响提交数、目标引用和发布计划，并在首次写操作前取得一次新的明确确认。
用户最初提出的重写请求不算这次二次确认。

每次调用都允许补充日期时间规则，不要静默复用上次日历。涉及地区工作日历
时，查询提交覆盖年份的官方安排并给出来源。时间窗口必须明确为半开区间，
例如 `[08:30,12:00)`。

## 重写前检查

读取项目说明并检查：

```bash
git status --short --branch
git branch --all --verbose --no-abbrev
git worktree list --porcelain
git config --get user.name
git config --get user.email
git remote --verbose
git rev-list --count <source>
git rev-list --count --merges <source>
git log --reverse --date=iso-strict --format='%H%x09%aI%x09%cI%x09%s' <source>
```

扫描全部可达历史中的数据库、环境文件、凭据、私钥、本地工具配置、截图和
个人路径。检查密钥时不要回显命中值。决定展开策略前，先判断 merge 是否
包含人工冲突解决。

禁止原地改写源引用。使用独立 worktree 或临时引用，保留无关脏改动和未跟踪
文件。任何可能从当前工作区移除真实数据库的操作，都必须遵守项目数据库备份
规则。

## 重建与清洗

按最旧到最新处理提交，并保留源提交到结果提交的映射。

- 连续线性提交直接载入源树，应用约定清洗，再提交结果快照。
- 从每个历史快照移除数据库和已确认敏感数据，不能只清理最终版本。
- 保留提交消息字节、清洗后的树、作者、提交者及约定元数据，并记录无法避免
  的签名失效。
- 展开 merge 时在合并位置插入侧分支提交；若存在人工冲突解决，把已核对的
  merge 最终结果折叠到最后一个侧分支提交。
- 只有约定明确要求时，才删除清洗后为空的提交。

使用精确引用和路径。禁止使用宽泛破坏性命令、自动强推、跳过钩子，或在本次
重写中顺手清理 dangling 对象。

## 应用日期时间规则

目标历史已经线性化并完成内容清洗后，使用
`scripts/rewrite_commit_times.py`。脚本读取每次调用都可扩展的 JSON 规则：

```json
{
  "timezone": "Asia/Shanghai",
  "holidays": [
    {"start": "2026-02-15", "end": "2026-02-23"}
  ],
  "workdays": ["2026-02-14", "2026-02-28"],
  "forbidden_windows": [
    {"start": "08:30", "end": "12:00", "when": "workday"},
    {"start": "14:00", "end": "21:00", "when": "workday"}
  ]
}
```

`holidays` 和 `workdays` 支持单日或闭区间。`workdays` 覆盖普通周末，
`holidays` 覆盖普通工作日，两者不能重叠。`when` 可为 `workday` 或
`all`。窗口采用半开、不跨日区间；跨午夜规则拆成两个窗口。工作日
`00:00`–`24:00` 全禁用时，提交会顺延到下一个可用日期。

规则文件写到仓库外，然后运行：

```bash
python3 scripts/rewrite_commit_times.py --self-test

python3 scripts/rewrite_commit_times.py \
  --repo <repo> \
  --source <clean-linear-ref> \
  --target <target-branch> \
  --rules <rules.json>

python3 scripts/rewrite_commit_times.py \
  --repo <repo> \
  --source <clean-linear-ref> \
  --target <target-branch> \
  --rules <rules.json> \
  --apply
```

默认只执行 dry-run。`--apply` 创建并验证新线性历史，把 TSV 映射写入系统
临时目录，再原子更新目标引用。目标分支已被任一 worktree 检出时拒绝执行。
若签名提交会失效，先取得明确同意，再添加 `--allow-signature-loss`。

## 验证与报告

完成前确认：

- 提交数、根数、merge 数、顺序符合约定，且没有缺失对象；
- SHA/日期时间及作者约定范围外的提交均未被改写；
- 除明确清洗内容和改写时间外，每组源/结果提交的消息、树、姓名和邮箱一致；
- 所有作者与提交者时间符合最终日历规则并保持严格递增；
- 禁止文件、个人路径和高置信密钥在可达历史中的命中数均为零；
- 最终树与源树的差异只有约定清洗项。

树内容变化时运行项目 lint、测试和构建；只有时间变化时，以树一致性证明替代
重复执行未变化代码。除非用户明确扩大范围，否则不修改源分支、当前工作区和
远端。最终报告新 HEAD、跳过提交、时间调整数量、验证结果、reflog 恢复点和
发布状态。
