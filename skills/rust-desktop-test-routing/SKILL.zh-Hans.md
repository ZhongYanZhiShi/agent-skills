# Rust 桌面测试路由

按真正运行被改动行为的层选择证据，仅浏览器运行成功不能证明原生桌面集成有效。

## 检查项目

读取项目说明、清单、受影响文件、现有测试、工作区脚本和 CI。选择命令前确认真实框架、目标及所属层。没有原生桌面目标受影响时，不适用本技能。

## 路由每项受影响行为

| 类别 | 边界 | 最小充分证据 |
| --- | --- | --- |
| 纯 Rust 逻辑 | 与框架无关的算法、解析、数据结构或状态转换 | 覆盖该逻辑的最小现有单元或集成测试 |
| 浏览器完备的渲染行为 | 无需原生桥接、模拟或仅桌面状态即可完整运行的 HTML/WebView UI | 项目中针对该具体行为的浏览器测试 |
| 桌面原生集成 | 操作系统或运行时行为：IPC、WebView 初始化、文件系统、数据库持久化、对话框、菜单、托盘、窗口、生命周期、重启恢复、单实例、事件循环、原生输入或渲染 | 原生测试工具、驱动真实运行时的集成测试，或实际执行该行为的桌面运行 |
| 混合行为 | 跨越多个类别 | 按所属层分别取得证据，单层通过不能代替其他层验收 |

把浏览器测试作为验收前，确认项目已为此目的使用该工具，且受影响行为在浏览器中完整可用。浏览器结果可辅助原生集成验证，不能替代。缺少必要执行路径时，把该行为标为**受阻**或**未验证**。

## 报告

逐项说明受影响行为的类别、所选命令或测试、结果及缺失证据，分开报告渲染器结果和原生运行时结果。

项目专属命令保留在项目说明、脚本和 CI 中，不在这里硬编码。
