# Shadcn 使用规范

结合项目实际情况应用 shadcn 规则，不把单个案例或修复方式变成通用固定方案。

## 工作流

1. 检查项目中实际安装的组件源码和真实组合方式，包括组件 API、状态样式、相关祖先元素、渲染结构、底层组件库，以及项目已有变体、令牌和工具类。只有能从项目代码而非上游假设解释相关行为时，本步才算完成。
2. 区分必须保留的行为和偶然存在的实现。选择改动前，先明确组件及其容器需要保留的行为，包括无障碍和交互要求。
3. 选择满足要求且影响范围最小的改动。优先使用已有组件 API、变体、令牌和组合模式。只有调用方普遍存在同一需求时才修改共享基础组件，否则适配当前用法。
4. 在真实渲染界面中验证所有受影响状态，包括键盘和指针交互、无效与禁用状态、目标断点、缩放、滚动、裁切、浮层和相关主题。复用项目已有检查；修改了非平凡代码时，留下能捕获回归的最小可运行检查。

## 规则

### 裁切容器内的聚焦标识

shadcn 控件可能通过超出元素边框盒的轮廓、环或阴影绘制聚焦状态，任何具有裁切效果的祖先元素都可能截断部分聚焦标识。

发生此问题时：

- 同时找到绘制聚焦标识的规则和执行裁切的祖先元素。
- 判断裁切是否有意用于滚动、圆角媒体、遮罩或动画，还是仅仅偶然存在。
- 根据上下文考虑移除或缩小不必要的裁切、把裁切移动到内部视觉层、增加局部留白、使用同样清晰的内嵌聚焦样式、调整已有聚焦环偏移，或把控件移出裁切边界。
- 比较可行方案对尺寸、滚动测量、圆角、点击区域、响应式布局、主题和复用范围的影响。这些方案没有固定优先级。
- 验证键盘聚焦标识在每一侧都完整可见，同时不破坏容器行为。

提高 `z-index` 无法越过 `overflow` 裁切。允许溢出可能破坏滚动、遮罩或圆角，固定增加内边距则可能改变几何尺寸和滚动范围。应保留预期行为，而不是机械保留某条 CSS 声明。

## 约束

- 保留无障碍名称、键盘操作、可见聚焦和 ARIA 状态。
- 通过已有变体、语义化令牌和工具类保持共享样式一致。
- 保留默认聚焦标识，或替换为同样清晰的表现。
- 若真实约束导致无法保留默认外观，应明确说明取舍。
